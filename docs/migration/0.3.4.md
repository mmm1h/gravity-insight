# 从 0.3.3 迁移到 0.3.4

状态：0.3.4 尚未发布；本文描述当前 `0.3.4` 源码相对 PyPI 0.3.3 的消费方变更。

## 先判断自己是否受影响

只使用 `gravity` 分析命令、SDK 查询或已发布 `skill-library-v1` Agent Skill ZIP 的消费方
不受本次破坏性字段迁移影响。只有直接调用 `gravity skills export-agent`，并解析所生成
`SKILL.md` YAML frontmatter 的消费方需要迁移。

## Agent Skill 运行时约束字段

0.3.3 的导出把运行时约束放在 Codex 当前规范不接受的顶层字段：

```yaml
compatibility: "Requires gravity-insight >=0.3,<0.4"
```

0.3.4 保留同一约束值，但移动到受支持的 metadata：

```yaml
metadata:
  gravity-runtime-requires: ">=0.3,<0.4"
```

- 受影响：对顶层 `compatibility` 做精确解析、allowlist 或展示的 Agent Skill 安装器。
- 不迁移：严格使用当前 Codex Skill frontmatter 规范的校验器会继续拒绝 0.3.3 导出；读取旧
  字段的自定义消费方在 0.3.4 会得到字段缺失。
- 迁移：改读 `metadata.gravity-runtime-requires`，并继续把它当静态兼容声明，而不是当前
  Runtime readiness、权限或依赖满足证明。
- 兼容期：无。旧顶层字段不是当前 Codex 支持的 frontmatter，0.3.4 直接移除；不增加会继续
  生成无效 Skill 的双写 shim。
- 能力保持：版本范围值未改变；Skill 的 GUIDE、SCHEMA、CLAIMS、identity、package digest 和
  Runtime 执行 Owner 均保留。

## 非破坏性 Skill Hub 新增

Skill Library 现在从同一 canonical manifest 生成 Runtime 包和 Host Agent Skill 两种投影，
并发布带摘要的 `agent-index.json`、对应 schema 与扁平 ZIP 资产。Agent Skill 可安装不提升
`readiness` 或 `validation`；`blocked`、`unvalidated` 或依赖未解析仍必须停止执行和业务结论。
