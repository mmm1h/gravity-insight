# Migrating to 0.3.11

## Model Claim Vocabulary: Hard Break

The five built-in Model contracts under
`gravity_insight/contracts/models/` previously expressed `claim_policy` in
natural-language phrases. All three tiers now carry canonical stable ids, the
same vocabulary Skill and Journey contracts already used:

| tier | before | after |
|---|---|---|
| `validated` | `deterministic scenario over caller-bound parameters` | `deterministic-scenario-over-caller-bound-parameters` |
| `scenario` | `unvalidated project calibration scenario` | `unvalidated-project-calibration-scenario` |
| `forbidden` | `causal claim` | `causality` |
| `forbidden` | `project accuracy guarantee` | `project-accuracy-guarantee` |
| `forbidden` | `guaranteed future outcome` | `guaranteed-future-outcome` |

`causality` is the existing Skill/Journey id, reused rather than duplicated. The
other four had no exact upper-layer counterpart and are kept as their own ids;
none was replaced by a broader or narrower near-synonym, because merging two
constraints of different scope silently widens one of them.

**Why this is a Hard break and not a rename.** A consumer that tested membership
against the prose strings now gets no match. Failing to match a *forbidden*
entry does not raise — it reads as "this claim is not forbidden". A caller
checking `"causal claim" in policy["forbidden"]` therefore flips from refusing a
causal assertion to permitting one, with no error anywhere. Treat this as a
safety-relevant change, not a cosmetic one.

**Migration.** Consume `claim_policy` values as opaque ids and compare them by
exact id. No natural-language aliases are retained, and none will be added:
an alias table would reintroduce the ambiguity this change removes. If you
maintain a mapping from claim ids to display text, that mapping belongs in your
own presentation layer.

**Not changed.** `models describe` / `models evaluate` field shapes, model URIs,
approval-selection logic, model artifacts, and every data-read capability are
unchanged. This release removes no read capability.

## Enforcement

`scripts/check_skill_journey_contracts.py` now covers the Model tier, and the
gate is fail-closed on two distinct failure modes:

- `model-claim-id-invalid` — the value is not a canonical id at all, e.g. it
  still contains spaces
- `model-claim-id-unknown` — the value is well-formed but is not a registered
  claim id

The second detector is what makes this more than a formatting rule: a
plausible-looking new id that nobody registered still fails.
