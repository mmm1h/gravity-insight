# Migrating to 0.3.11

## Model claim policy: Hard break

**受影响**：读取 `gravity_insight/contracts/models/*.json` 的 `claim_policy` 并按字符串匹配的消费方。

**旧 → 新**（三档全部改为规范稳定 ID）：

| tier | 旧 | 新 |
|---|---|---|
| `validated` | `deterministic scenario over caller-bound parameters` | `deterministic-scenario-over-caller-bound-parameters` |
| `scenario` | `unvalidated project calibration scenario` | `unvalidated-project-calibration-scenario` |
| `forbidden` | `causal claim` | `causality` |
| `forbidden` | `project accuracy guarantee` | `project-accuracy-guarantee` |
| `forbidden` | `guaranteed future outcome` | `guaranteed-future-outcome` |

`causality` 复用 Skill/Journey 已有 ID。其余四个没有精确上层对应物，保留为独立 ID，
不用更宽或更窄的近义约束代替——合并两个范围不同的约束会静默放宽其中一个。

**不迁移的后果**：匹配旧字符串不再命中。**漏匹配 `forbidden` 不会报错**，读起来是
"未被禁止"，于是调用方会开始放行一条它以前拒绝的因果断言，全程静默。按安全相关变更处理。

**迁移**：把 `claim_policy` 的值当作不透明 ID 按精确值比较。**不保留自然语言别名，
今后也不会加**——别名表会把这次消除的歧义重新引入。需要展示文案的，映射放在自己的展示层。

**旧写法移除计划**：本次即移除，无过渡期。`models describe`/`evaluate` 的字段形状、
模型 URI、审批选择逻辑与全部数据读取能力均未改变。

## 门禁

`scripts/check_skill_journey_contracts.py` 现覆盖 Model 层，两个 fail-closed 判据：
`model-claim-id-invalid`（不是规范 ID，例如仍带空格）、`model-claim-id-unknown`
（格式合法但未登记）。后者才使它不只是格式规则——凭空造的合法 ID 同样失败。

## Capability Validation evidence v2

**受影响**：直接读取私有 Capability Validation run/summary JSON，按 v1
`schema_version` 分支，或固定读取
`agent-runtime/capability-validation-summary.v1.json` 的维护工具。

新采集的 run 使用 `gravity.capability-validation-run.v2`；离线汇总使用
`gravity.capability-validation-summary.v2`，写到
`agent-runtime/capability-validation-summary.v2.json`。每个 outcome 新增两个可选诊断：

```json
{
  "response_drift": {
    "schema_version": "gravity.response-drift.v1",
    "direction": "response",
    "classification": "additive",
    "fields": [{"path": "/data/new_field", "observed_type": "string"}]
  },
  "error_detail": {
    "code": "CONTRACT_CHANGED",
    "category": "upstream"
  }
}
```

`response_drift` 只包含规范化 JSON Pointer 和 JSON 类型；`error_detail` 只包含 Runtime
已知机器错误码以及 `caller/upstream/local/unknown` 分类。响应值、错误消息、错误 field、
`next_action`、异常文本和 unsupported item 均不持久化。

汇总器继续读取已有的 v1 run，历史 outcome 没有诊断时保持字段缺失，不伪造也不要求重跑。
它只生成 v2 summary，不继续双写 v1 文件；否则两个文件都会看起来像当前权威摘要。未迁移的
严格 v1 parser 会拒绝 v2，固定读取旧文件名的工具会停留在旧证据。迁移时改读 v2 文件、按
v2 schema 校验，并把两个诊断字段视为可选：旧 run 无法补回从未保存的明细。

此次版本升级不删除采集、离线汇总、历史 run 读取或 Trust 判定能力；`summarize` 命令返回的
计数形状保持不变。回滚时必须同时恢复 run/summary schema version、summary 文件名和 outcome
形状，不能只恢复旧文件名。
