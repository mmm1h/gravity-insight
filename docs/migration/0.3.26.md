# Migrating to 0.3.26

## Order-detail record completeness

`analysis.order_detail.list` contract version 4 declares `event_pay_id` as its
record identity field. SDK and CLI results retain structural page closure in
`structural_completeness` and add `record_completeness` with only bounded counts:
identified items, unidentified items, repeated identities, and duplicate items.
No identity value is returned by the audit.

Consumers that previously accepted `completeness=complete` from
`has_more=false` plus `returned_items=total_items` must now also require
`record_completeness.status=complete`. When identities are missing or repeated,
overall completeness is `unknown`; continue to retain the rows only as an
uncertified collection and use an independently complete authorized ledger for
financial payer statistics. Do not deduplicate the rows and claim a census.

There is no compatibility mode. The previous claim could certify repeated
retrievals as complete, so it is removed in 0.3.26 rather than retained behind
an alias. Reading, filtering, pagination, projected fields, and returned rows are
unchanged.

## Capability preservation

The canonical `work-dashboard` tree contains no consumer of
`analysis.order_detail.list`, `event_pay_id`, or its pagination audit. Repository
and runtime tests preserve every returned row and all existing request fields.
This change removes only an unsupported unique-record completeness claim; it does
not remove data-reading capability or infer whether Gravity pagination or the
adapter produced a duplicate.
