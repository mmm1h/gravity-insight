# Migrating to 0.3.22

## Event conditions

Event Analysis Spec, SDK, CLI, Plan, and saved/dashboard Event re-execution now
reject `GT/GTE/LT/LTE` before dispatch. Replace them explicitly with
`GREATER/GREATER_EQUALS/LESS/LESS_EQUALS`, respectively; keep the field and values
unchanged. There is no compatibility alias or deprecation period. Non-migrated
Event callers receive `INPUT_INVALID`, an exact condition path and replacement.

This restriction is Event-only. The shared operator set used by Segment rules
(including static-count `GTE`), detail reads, and other Analysis kinds is intact.
Their upstream acceptance was not inferred from Event evidence. Dashboard/saved
configuration validation uses the selected Analysis kind, not a global alias ban.

## Condition values

Compact `WITH_VAL` and `WITHOUT_VAL` may omit `value`; compilation supplies the
wire-required `value: []` without modifying the original spec. All other condition
operators must provide an explicit scalar array. Raw wire conditions must include
`value`, including `[]` for the two valueless operators. Missing values now fail
locally rather than reaching upstream. Existing explicit arrays are preserved.

## Percentiles

Event `{"field":"<numeric-property>","aggregation":"Quantile_50"}` now emits
`{"field":"<numeric-property>","name":"Quantile","quantile_level":50}`.
Alternatively use `aggregation=Quantile, quantile=50`. Bare `Quantile` without a
percentile, or a suffix conflicting with `quantile`, receives `INPUT_INVALID`.
Use the supported aggregation rather than substituting an average for a median.
The Event translation is not applied to unverified non-Event target encodings.

## Error handling

The reviewed input rejections from #247/#239/#244 are `INPUT_INVALID`,
`category=caller`, `retryable=false`. Follow `next_action`; do not lower batch
concurrency for them. A catalog-listed property is not proof that an event has
bound or populated it. Keep a rejected grouping dimension unknown; do not infer
zero activity. The unbound-property mapping is the observed exact sentence, not
a blanket ban on that property in every event. Unknown sentences keep the
request-sensitive #21/#23/#24 behavior.

## Evidence and capability preservation

On 2026-10-04, single-App read-only `analysis.event.query` probes used one
completed natural day. Four pairs changed only the condition operator: each
short form returned HTTP 200/code 1004 (`operator:GT非法`, `operator:GTE非法`,
`operator:LT非法`, `operator:LTE非法`); its long form returned code 0/success.
Two absent/empty pairs established the two valueless operators: missing returned
code 1004 with prefix `参数缺失,value:`; `[]` succeeded. Its embedded payload is
not published or echoed. `Quantile_50` returned `统计指标不正确: Quantile_50`;
the split target succeeded. The grouping probe returned code 1004 and
`处理事件属性分组错误：该事件未绑定属性[$pay_reason]`.

Quantile source: [public Event bundle](https://web.gravity-engine.com/assets/Event-BKh0ym6c.js),
function `Xe`: split `targetNameValue` at `_`, send base `name` and numeric
`quantile_level`. Existing operation contracts already permit those target keys;
no operation route, response projection, or privacy contract was expanded.

No proven read capability was removed: all four explicit comparison replacements
succeeded with unchanged filters; valueless filters succeed with the compiler's
empty array; median now has a successful wire encoding. Non-Event operator
vocabularies and existing explicit values remain. No blanket missing-property
ban was introduced, and no missing data is fabricated. Non-Event alias/quantile
acceptance and long-term stability of the group rejection remain unverified.

Read-only canonical `work-dashboard` audit found no Analysis short aliases and no
omitted-value `WITH_VAL`; `tools/reporting/wechat_ltv_drivers.py` already supplies
`value=[]`. No consumer edits were required or made. Frozen outputs and unrelated
`LT` variable names are not Analysis conditions.
