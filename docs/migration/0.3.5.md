# 从 0.3.4 迁移到 0.3.5

0.3.5 将业务 Skill 的唯一分发入口收敛到 Skill Hub。Runtime wheel 不再携带 AP 成本异常
定位或其他项目业务 Skill，R01 Journey 则继续保留，并通过项目精确 lock 与本地 CAS 解析
同一个 canonical Skill。

## 破坏性变化

- Python 公开符号 `LocalSkillResolver` 已移除。
- `gravity skills` 的旧 `export-agent` 子命令已移除；宿主 Agent Skill 必须从同一 Library Release 的
  `agent-index.json` 选择并校验 archive，再交给宿主自己的安装机制。
- `gravity skills list` 和 `gravity skills show` 不再读取 wheel 内置项，必须提供
  `--state-root`，并只读取已经同步且通过合同验证的 Hub snapshot。
- `gravity.execution-snapshot.v1.skill.resolution` 只接受 `locked`；旧的 `unlocked`
  snapshot 会失败关闭，不提供兼容别名。
- `analysis.merge2.ap-cost-anomaly-localization` 运行前必须在调用项目根目录提交精确
  `gravity.skills.lock.json`，并在对应 Runtime state root 的 CAS 中存在核验通过的包。

## 迁移步骤

从 `skill-library-v3` Release 下载 `source.json`，然后执行：

```powershell
gravity skills sync --source source.json --state-root <state-root>
gravity skills list --state-root <state-root>
gravity skills show skill://gravity.game/ap-cost-anomaly-localization@1.0.0 --state-root <state-root>
gravity skills lock --skill skill://gravity.game/ap-cost-anomaly-localization@1.0.0 --output gravity.skills.lock.json --state-root <state-root>
gravity skills fetch --source source.json --lock gravity.skills.lock.json --state-root <state-root>
gravity skills verify --lock gravity.skills.lock.json --state-root <state-root>
```

将生成的 `gravity.skills.lock.json` 纳入调用项目版本控制。CAS 和同步状态属于本机状态，
不得提交。另一个设备使用同一项目 lock 和 `source.json` 执行 `sync → fetch → verify` 即可
取得相同 package digest。

## 能力保持

- R01 的 Journey ID、输入合同、现有 Plan 执行 owner、请求预算、Operator、Semantic、
  Context、allowed/forbidden claims 和 Analysis Result 保持不变。
- 当前生产完整性仍为 `unknown`，因此依赖齐全时仍以
  `COMPLETENESS_INSUFFICIENT`、零目标请求失败关闭；这次迁移不伪造可执行状态。
- 合成的 complete/fresh 路径继续证明精确 locked Skill 能通过原执行 owner 产出同形结果。
- `skill-library-v1` 与 `skill-library-v2` 保持不可变，旧 lock 继续按原 URL 和摘要获取；
  0.3.5 的新 R01 lock 使用 `skill-library-v3`。

## 回滚

回滚 Runtime 和调用项目 lock 到同一个 0.3.4 snapshot。不要把 0.3.5 Runtime 与旧
`unlocked` execution snapshot 混用，也不要在缺少 CAS 时恢复 wheel 内置副本作为 fallback。
