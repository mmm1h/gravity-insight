# Migrating to 0.3.23

## Funnel grouping

Funnel Analysis requests (compact Spec, SDK, CLI, Plan, and raw `analysis.funnel.query`)
with more than one non-time grouping dimension now receive `INPUT_INVALID` before
dispatch. `error.field` points at the first extra dimension, and `unsupported_items`
lists every dimension that would have been dropped. Keep exactly one grouping
dimension per Funnel request. For another dimension, send one request per known
value with an equality filter, or use Event Analysis for a multi-dimension
breakdown. There is no compatibility mode.

## Evidence and capability preservation

On 2026-10-05, read-only `analysis.funnel.query` probes on one completed natural day
grouped by two user properties, and by one event property plus one user property,
at `time_grain=total`. Both returned HTTP 200/code 0 with `aggregate_date.group`
keyed only by the first dimension's values, and each group held only per-step
counts. At `time_grain=day` the same pair returned date-priority aggregates, which
the existing `contract_changed` guard already rejects. A single grouping dimension
remains accepted and returns the same groups as before, so no read capability is
removed. A request with several dimensions never returned the extra ones.

The canonical `work-dashboard` audit found 21 Funnel specs, none with more than one
grouping dimension. No consumer edits were required.
