# 从 0.3.2 迁移到 0.3.3

状态：0.3.3 已于 2026-09-01 发布；本文描述 `0.3.3` 相对 PyPI 0.3.2 的消费方变更。

## 先判断自己是否受影响

| 消费方式 | import 改名 | 环境变量改名 | schema_version 改名 |
| --- | --- | --- | --- |
| 只调用 CLI，不解析 JSON | 不受影响 | 仅在设置 auto-upgrade 变量时受影响 | 不受影响 |
| Python `import gravity_sdk` | 受影响 | 视配置而定 | 视解析逻辑而定 |
| 设置 `GRAVITY_SDK_*` | 不受 import 影响 | 受影响 | 不受影响 |
| 按 `schema_version` 精确分支 | 不受 import 影响 | 不受影响 | 受影响 |

独立 CLI 消费方升级前应在自己的仓库中搜索
`GRAVITY_SDK_`、`gravity-sdk.doctor.v1` 和
`gravity-sdk.install-consistency.v1`。本迁移说明不假定任何仓库的搜索结果。

## 1. Python import root：硬破坏

0.3.2 的分发名已经是 `gravity-insight`，wheel 文件名也是
`gravity_insight-0.3.2-py3-none-any.whl`，但 wheel 内的模块目录仍是
`gravity_sdk/`，entry point 是 `gravity = gravity_sdk.__main__:main`。0.3.3 才把
模块目录和 entry point 改成 `gravity_insight`。因此 `gravity` CLI 名没有改变，只用
CLI 的消费方不需要为这一项改动。

迁移所有 Python import：

```python
# 0.3.2
import gravity_sdk
from gravity_sdk import GravitySDK

# 0.3.3
import gravity_insight
from gravity_insight import GravitySDK
```

- 受影响：直接 import 包根、子模块或类型注解字符串的 Python 消费方。
- 不迁移：在只安装 0.3.3 的环境中，首次旧 import 抛出
  `ModuleNotFoundError: No module named 'gravity_sdk'`。
- 兼容期：无。0.3.3 不提供 `gravity_sdk` shim；旧写法只能继续配合 0.3.2 使用。
- 核实方式：`git show v0.3.2:pyproject.toml` 与
  `git ls-tree v0.3.2:src` 分别显示旧 entry point/`gravity_sdk` 目录；当前
  `pyproject.toml` 指向 `gravity_insight.__main__:main`，当前 `.venv` 的
  `import gravity_sdk` 实测产生上述异常。

## 2. 环境变量：软破坏

当前源码对旧名的行为不是一刀切：三个 auto-upgrade 变量仍是 fallback，另一个旧
home 变量只作为凭据文件清理键存在。

| 0.3.2 旧写法 | 0.3.3 主写法 | 0.3.3 对旧名的真实行为 |
| --- | --- | --- |
| `GRAVITY_SDK_AUTO_UPGRADE` | `GRAVITY_INSIGHT_AUTO_UPGRADE` | fallback；仍能启用检查 |
| `GRAVITY_SDK_PINNED_VERSION` | `GRAVITY_INSIGHT_PINNED_VERSION` | fallback；仍能按当前版本禁用检查 |
| `GRAVITY_SDK_AUTO_UPGRADE_TARGET_PYTHON` | `GRAVITY_INSIGHT_AUTO_UPGRADE_TARGET_PYTHON` | fallback；仍能选择目标解释器 |
| `GRAVITY_SDK_HOME` | 无 | 不读取；保存、清除或迁移凭据时从 account env 文件删除 |

三个 fallback 都遵循“新名存在即采用新名”，即使新名值为空或为 `0`，也不会再读取
对应旧名。建议现在直接改名，不要同时保留两套值：

```text
GRAVITY_INSIGHT_AUTO_UPGRADE=1
GRAVITY_INSIGHT_PINNED_VERSION=0.3.3
GRAVITY_INSIGHT_AUTO_UPGRADE_TARGET_PYTHON=C:\path\to\python.exe
```

- 受影响：设置前三个 auto-upgrade 变量，或仍把 `GRAVITY_SDK_HOME` 当配置读取点的
  启动脚本、CI 与封装器。
- 不迁移：0.3.3 中前三个旧名单独使用时不会报错；若新旧名并存，旧值被静默忽略。
  `GRAVITY_SDK_HOME` 当前不会生效，并可能在凭据维护时被删除。
- fallback 移除后：旧 enable 名将不再启用检查，旧 pinned 名将不再抑制检查；若只保留
  旧 target 名且确有待安装更新，计划会以
  `error: Gravity SDK cannot plan update <version> (target interpreter is not configured). This command was not run.`
  失败。
- 兼容期：前三个 fallback 在 0.3.3 仍可用，移除版本与日期未定，需 Owner 决定；
  `GRAVITY_SDK_HOME` 已经只是 cleanup key，没有可承诺的功能兼容期。
- 核实方式：`src/gravity_insight/auto_upgrade.py` 的 `_environment_value` 明确实现新名优先
  的 fallback，`tests/test_auto_upgrade.py` 分别覆盖三个旧名和并存优先级；
  `src/gravity_insight/credential_storage.py` 的三个 `remove_keys` 集合只删除
  `GRAVITY_SDK_HOME`，全仓没有读取它的 Runtime 路径。

## 3. 安装诊断 schema_version：硬破坏

迁移精确字符串分支；这里不只是前缀变化，版本号也从 `v1` 升到 `v2`：

```text
gravity-sdk.doctor.v1              -> gravity-insight.doctor.v2
gravity-sdk.install-consistency.v1 -> gravity-insight.install-consistency.v2
```

- 受影响：读取 doctor 安装失败 envelope 或 install-consistency 结果，并对
  `schema_version` 做 allowlist、反序列化或分支的消费方。
- 不迁移：Runtime 不会同时输出旧值；严格消费方会进入自己的 unknown/unsupported
  schema 分支。该错误由消费方实现决定，Runtime 没有一个可承诺的统一异常文本。
- 兼容期：无。0.3.3 直接输出两个 `gravity-insight.*.v2` 值。
- 核实方式：`git grep` 在 `v0.3.2` 的源码中只找到上述两个
  `gravity-sdk.*` schema_version；当前值分别定义在
  `src/gravity_insight/doctor_cli.py` 和 `src/gravity_insight/install_doctor.py`，对应测试
  精确断言两个新值。

`gravity.*`（例如 `gravity.result-audit.v1` 和
`gravity.agent-module-reference-checkpoint.v2`）属于工具/门禁域，不在本次迁移范围，
没有改变，也不应重写。现存 `https://gravity-sdk.local/...` JSON Schema `$id` 也不是
本节的 `schema_version` 字段，本次未迁移。
