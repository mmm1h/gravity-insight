# v3.6 Gravity Insight 受控原子读取层

## 决议

新增 `tools.gravity_insight` 与 `work_dashboard.gravity_insight`，把 Gravity Web API 建成独立的受控原子读取层。它与 `tools.gravity` 并列：前者读取多维报表、推广、素材、归因等 Web 产品数据，后者继续只承载既有 SQL 聚合产品与 Evidence readiness；双方复用同一份本地账号凭证，但不共享产品状态或扩大任意 SQL 边界。

公共能力以稳定 `operation_id` 标识。上游 HTTP 方法、v1/v2/v3 路径、分页、请求形态和响应差异只存在于版本化 manifest 与必要 codec 中。调用者只能提交登记操作及其声明字段，不能传入任意 URL、方法、请求头或覆盖固定参数。领域命令只组合原子操作，不直接访问网络。

## 执行与扩展边界

- 核心执行器统一负责认证刷新、字段校验、请求构造、分页、限流、重试、响应投影、语义错误和批量部分失败。
- capability catalog 使用 `stable`、`experimental`、`permission_unavailable`、`blocked_privacy`、`blocked_write`、`deprecated` 表达覆盖状态；只有 `stable` 默认可执行。
- 新增读取能力必须先登记 endpoint、只读理由、输入/输出契约、隐私策略和最小 live probe，再以脱敏 fixture 通过合同测试；未知或仅静态发现的接口不能直接升级为 stable。
- 上游路由升级只修改 manifest/codec 和 contract version，不修改稳定 operation id。标准平台通过共享 codec 登记，特殊平台只覆盖差异字段。
- “全读取覆盖”以所有已发现接口均有明确 catalog 状态为完成标准，不以开放裸 HTTP 透传为手段。

## 分析模块与 SQL 定位

Gravity 的事件、漏斗、留存、分布和属性分析使用结构化请求和聚合响应，适合作为日常行为分析的主路径。这些能力以独立 `analysis.*` operation 登记，事件名、属性名、目标、时间范围、分组和条件通过实时元数据与深层请求契约校验；不接受 SQL 正文、任意 URL 或未登记 wire 字段。Analysis 同时提供订单、拆单、变现、用户属性、单用户事件流、回传日志、分群版本/趋势/成员、看板与模板等原子读取。`user_level` 合同允许输出 manifest 明确登记的 UID、ClientID、设备、订单、trace 与成员字段，使单用户和特定分群分析不再被聚合层阻断。

分析模块不等于通用 SQL 执行器。已登记的业务 SQL 大量使用跨表 JOIN、CTE、窗口函数、UNION 和自定义 CASE 口径，这些无法由标准事件/漏斗/留存模型等价表达。因此最终分工为：标准聚合分析优先使用 Insight Analysis；SQL 继续承担用户分层、复杂跨表/自定义口径、可复现证据和候补查询。Gravity 页面中的“SQL 工作台”仍属于 SQL 通道，不因为位于分析菜单就被视为结构化分析能力。

## 认证、数据与隐私

账号密码登录沿用 Gravity 前端协议和 `.env.gravity.local`，token 作为不透明值使用。并发失效只允许 single-flight 刷新一次；本地更新保持原子写入和既有权限收紧。凭证、请求头和登录 payload 不进入 stdout、日志、fixture、报告或 Git。

Insight 与既有 SQL 门面复用同一个进程级 HTTP runtime：共享长生命周期 Session、CredentialProvider、Cookie、连接池和按目标 host 分桶的限流预算。Insight 默认并发仍为 6，显式批量调用上限为 24，连接池保留第 25 条连接给 401 恢复路径上的登录请求。2026-08-08 对单日、单事件的 Analysis 聚合执行 24-worker 在线探针，24/24 成功、零契约漂移，总耗时 2.655 秒；同时仍由每 host 默认 10 RPS 限流预算控制实际发送速率，因此“24 worker”不等于无界 24 QPS。SQL 根据独立探针另设 Runtime 与门面双重进程级上限 2。限流只在锁内预留时隙，在锁外等待，避免并发退化为串行。普通退避与请求间隔均带随机抖动，`Retry-After` 作为同 host 的共享冷却时间。浏览器公共头由同一 Chrome major 生成，无法探测本机 Chrome 时固定回退到 150。

SQL 不伪装成 manifest 原子操作，也不获得裸 HTTP 旁路。它使用独立的受控门面，只允许 `POST https://api-insight.gravity-engine.com/custom_sql/api/sql/execute`、页面来源 `https://bi.gravity-engine.com`，请求体精确为 `{sql, tabId: "1"}`；调用方不能提供 host、路径、方法、请求头或 token。Insight 仍必须消费 PolicyEngine 的一次性 manifest 授权，公共 runtime 不能直接发送 Insight 请求。该分层让两条链路共享认证、会话、限流、重试和错误模型，同时保持各自的请求策略边界。

原子结果保留经契约投影后的上游业务结构；未登记的新字段默认隐藏并报告 contract drift。字段叶子统一声明为 JSON scalar 联合类型（`null | boolean | finite number | string`），因为上游 ID 存在整数/字符串双形态；scalar 与 object/array 互换、非有限数字或非 JSON 值均按 drift 隐藏，嵌套 object/array 必须有逐路径合同或显式 `opaque_json_item_keys` 动态配置合同。`schema_fingerprint` 记录本次观测形态，不把联合类型内的合法 primitive 切换误报为合同变化。普通 `user_level` 操作可返回业务所需的用户、设备、订单和成员明细；Authorization、Cookie、token、密码、secret 等会话凭证始终递归剔除。读取结果只返回给当前调用方，不自动写入仓库、不发布 Evidence，也不执行导出、上传、分享、授权或其他写操作。

## 验收

截至 2026-08-08，目录登记 136 个原子能力：124 个 stable、5 个 experimental 且全部不可执行、1 个 permission_unavailable、5 个 blocked_privacy 和 1 个 deprecated。124 个 stable 操作全部具备可重复最小探针；本轮以 6 worker 在线验证为 38 success、71 empty、15 permission_unavailable，零 contract_changed、语义错误和合同告警。`permission_unavailable` 表示当前账号缺少看板、分群、订单或首用户等探针父数据，不代表 operation 合同失败。

Analysis 现登记 45 个原子能力，其中 43 个 stable：除事件/漏斗/留存/分布/属性聚合外，已覆盖事件与用户属性值枚举、分群规则命中人数评估、分群定义/版本/人数趋势/成员、订单/拆单/变现、用户详情、单用户事件流、回传日志、账号成员目录、任务事件、隐藏字段、保存配置、看板/成员/默认筛选和模板。对应在线最小验证为 14 success、14 empty、15 permission_unavailable，全部零合同漂移和告警。Analysis 仅剩 2 个 AI conversation/message loader 为 experimental 且不可执行：当前官方 bundle 只创建 loader，未发现实际调用、请求 wire 或响应消费，不能伪造为已支持。另 3 个 experimental 是未验证 OpenAPI namespace 候选；其余非 stable 项均不属于 Analysis 主查询链。

Registry 门禁必须拒绝未知 operation、非白名单 host/path、写接口和未声明字段且不发出网络请求；每个 stable 操作必须具备完整 manifest、结构 fixture 或合同测试以及明确分页/错误规则。离线 smoke 不连接 Gravity，在线 probe 只允许单日、单页、最小字段的读取请求。
