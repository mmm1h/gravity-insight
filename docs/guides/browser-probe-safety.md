# Gravity Insight 浏览器只读探测规范

Gravity Insight 的正式查询、`probe`、`probe_all` 和 CLI `doctor --live` 只通过受控 HTTP SDK 执行，
不得依赖浏览器页面、页面路由或 DOM 自动化。

## 为什么不能复用报表页面

Gravity 多维报表编辑态用同一个 dirty 状态保护两类离开动作：

- Vue Router 的离开守卫显示“您修改的报表尚未保存，请问是否要退出？”；
- `beforeunload` 阻止刷新、关闭标签或整页导航。

报表名称、维度/指标、筛选、排序和计算配置等变化都会设置 dirty。即使探测本身只想读取，
复用一个已经 dirty 的用户标签并导航离开，也会触发保护提示，并可能干扰用户真正未保存的工作。

## 只读摸排边界

1. 优先读取静态 bundle、路由定义和网络契约；正式能力验证直接调用 SDK operation ID。
2. 只有必须确认页面行为时才打开独立、一次性的浏览器标签；不得接管或导航用户现有标签。
3. 不进入 `#/pivotReport` 编辑态，不点击报表名称、字段、筛选、排序、计算配置、保存、分享、订阅或导出控件。
4. 不注入脚本清除 dirty、不移除路由守卫或 `beforeunload`，也不自动确认“退出”。出现提示时保留页面并停止该探测。
5. 仅关闭本次探测创建的标签；用户原有标签和未保存状态必须原样保留。

静态资源或页面检查得出的候选接口仍需进入受控 manifest、Policy 和响应投影后，才能成为 SDK 能力；
浏览器探测本身不是生产查询路径。
