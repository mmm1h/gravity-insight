# 抖小平台数据分析口径

更新日期：2026-07-29

适用范围：后续所有抖小平台数据分析。本文只定义用户范围、活跃分母和与支付口径的连接方式，不提供活动归因或因果判断。

## 两个不可混用的归因口径

### A. 业务方指定的历史连续抖小买量口径

用于分析对象包含 2026-07-01 以前注册用户、且业务方明确要求与旧报表保持连续可比的场景。本次四活动专题已明确指定该口径；谓词来自旧版四活动 SQL 和历史报告：

```sql
SELECT id AS user_id
FROM `default`.`user`
WHERE app_id = 29034827
  AND SUBSTR(COALESCE(get_json_string(properties, '$.$first_scene'), ''), 1, 2) = '02'
  AND COALESCE(CAST(click_company AS VARCHAR), '') <> ''
  AND COALESCE(CAST(advertiser_id AS VARCHAR), '') <> ''
GROUP BY id
```

- `app_id=29034827` 固定抖小平台，`$first_scene` 前缀 `02` 固定抖小宿主。
- `click_company` 与 `advertiser_id` 复用旧版实际字段和非空判断。`advertiser_id` 是历史归因中的广告主标识；当前 `default.user` 不存在已核验的 `project_id`、`promotion_id`、`campaign_id`、`adgroup_id`、`ad_id`、`creative_id` 或 `material_id`，因此不得把 `click_company` 猜测或改名为某个确定的“计划 ID”。
- 2026-06-01—07-28 四活动专项包含更早注册、但在窗口内活跃或付费的用户，统一使用本口径，不使用 ``user_$ea_click_company``。

### B. 2026-07-01 起新注册用户归因口径

根据本次专题的业务方说明，``user_$ea_click_company`` 只对 **2026-07-01 起注册**的用户生效。只有查询已先用权威注册时间字段限定该注册批次时，才可使用：

```sql
SELECT id AS user_id
FROM `default`.`user`
WHERE app_id = 29034827
  AND `user_$ea_click_company` = 'bytedance'
GROUP BY id
```

在本次业务规则下，该字段不能回溯识别更早注册用户；更早注册用户字段为空时，不得据此判定为自然量。2026-07-28 的 Gravity 只读聚合只核验了字段存在于 `default.user`、不是 `default.event` 的直接列，且无前缀的 `ea_click_company` 不存在；**尚未独立核验“注册时间 × 该字段 × A 口径命中”的交叉分布**。因此，这一时间边界当前是业务输入，不是本批次数据证明；在完成交叉核验前，不得把 A 自动提升为所有新分析的默认口径。

### 选择规则

- 分析人群可能包含 2026-07-01 前注册用户且业务方明确要求历史连续可比时，使用 A，不能用 B 排除早注册存量用户；报告同时披露注册时间交叉核验是否完成。
- 只有明确限定 2026-07-01 起注册批次时才使用 B；该批次内不再追加 A 的字段缩窄范围。
- 不自动拼接 A、B，也不按比例外推。引用结论时必须注明所用口径和注册批次边界。
- 此前已发布的报告、SQL 结果和证据快照保留原口径，不静默改写；仍处于工作态的报告可在完整重算后原位修正。

## 活跃与支付

- 窗口统一使用 `Asia/Shanghai` 左闭右开时间范围。
- 窗口活跃用户使用 `$MPLaunch` 去重用户作为代理；它表示窗口内小程序启动或回前台，不等于活动曝光、活动进入或有效触达。
- 收入、订单和买家使用 [Gravity 支付口径](Gravity支付口径.md) 的 `gravity_revenue_v1`、`gravity_order_count_v1` 和 `gravity_buyer_count_v1`。
- 支付事件先与上述用户范围按 `user_id` 相交，再做窗口和商品/活动条件聚合。
- 当前专题消费者在执行前必须检查 `$MPLaunch`、`$PayEvent` 和符合范围的用户是否存在，并记录缺失金额、无效金额、缺失商品原因及订单键回退行数。

## 可执行消费者

数据源 readiness 仍由 `tools.gravity` 提供；专题查询由归属 `30_专题工作区` 的固定消费者执行：

```powershell
gravity sql status --json
python -m tools.campaign.analytics list --json
python -m tools.campaign.analytics run <consumer-id> [--family FAMILY] --format json
```

消费者只能执行代码登记且内容哈希匹配的聚合 SQL。它不接受 SQL 文本、任意文件路径或开放式参数。

## 使用边界

- 必须先使用目标平台对应的 `app_id`；抖小为 `29034827`，查询其他平台时不得沿用该值。
- 历史连续分析使用 A；仅限 2026-07-01 起注册的分析使用 B。两者不得在同一分母中混用。
- 对 2026-07-01 起注册用户的 B 口径，不用 `$first_scene`、`click_company`、`advertiser_id` 再次收窄范围。
- 对包含 2026-07-01 前注册用户的历史分析，不使用 ``user_$ea_click_company`` 空值排除用户。
- 不把 ``user_$ea_click_company`` 非 `bytedance` 或空值用户解释成某个确定的自然量来源。
- 不把 `$MPLaunch` 活跃用户当作活动曝光或 assignment。
- 不把 GM 固化名单、默认档配置或支付结果拼成精确转化漏斗。
- 没有真实 assignment、exposure、outcome 和随机对照时，不宣称活动、分层或价格带来因果增量、ROI 或 uplift。
- 行为支付收入不是会计净收入或财务对账结果。
