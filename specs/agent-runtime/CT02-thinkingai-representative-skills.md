# CT02 Representative ThinkingAI Skills

| Field | Value |
| --- | --- |
| Parent directive | `gravity-agent-runtime/v9.1` via `directive.json` |
| Status | `specified` |

| Parallel group | `content-b` |
| Main integration | Frozen until whole program completion |

## Outcome

Three to five independently authored representative Skills validate the stable Skill/Semantic/Operator/Context dependency model and Team Hub Stage A across materially different readiness shapes.

## Selection Gate

The set must cover:

```text
Capability-only
project Semantic dependency
deterministic Operator dependency
required Context dependency
optional blocked Model or Action dependency
```

Selection is based on architecture coverage and real Gravity analysis value, not ease of implementation or vendor prominence.

## Current Baseline

CT01 provides source topics; R09A provides Core Skill Runtime and R09B provides Team Hub binding. R01's Built-in reference Skill is an architectural slice and does not by itself prove content migration diversity or Hub synchronization. R09C is required only for a representative Skill that explicitly needs external Context.

## Scope

- Write independent question, method, dependencies, stops, output and claim policy.
- Package and lock each representative Skill through R04.
- Bind real Gravity Journey/Eval cases.
- Keep unsupported dependencies precisely blocked.
- Feed only general schema defects back through an explicit architecture/requirement amendment.

## Non-goals

- No copying of source wording or vendor evidence.
- No Runtime route/executor modifications to make a third-party topic appear executable.
- No claim that the representative set completes the full migration.

## Machine Contract

Each Skill has specification/lifecycle/readiness/validation axes, exact provenance references, package digest, dependency graph, claims and output schema. Current Gravity evidence alone controls executable/validated state.

## Safety And Operations

Context injection and marketing-number leakage tests are mandatory. Any action dependency remains blocked until R12. License review must be approved before package distribution.

## Acceptance

- All required dependency shapes are represented.
- Team members resolve/install identical locked packages.
- Happy/empty/partial/gap/invalid and claim-boundary evals pass.
- Blocked Skills remain useful for discovery without executable argv.
- No core routing or execution special case is introduced.

## Verification

Package/lock parity, Journey can-run, eval corpus, dependency failure, provenance/license, marketing leakage, prompt injection, request/context budgets and full gates.

## Rollback And Exit

Representative packages can be revoked from new use without changing Runtime schemas. A failed representative identifies a requirement blocker; it does not lower safety or completeness rules.

## Canonical Owners

Representative Skill sources/packages, migration matrix readiness, Journey/Eval artifacts and Hub catalog entries.
