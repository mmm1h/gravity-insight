# 32 条已闭环动线对抗式复核提案

## 目标

独立验证 `docs/analysis-journeys.md` 当前标为已闭环的 32 条产品动线，不把文档声明本身当作证据。产出逐条、可复现、可区分“坐实 / 疑似 / 离线验不了”的缺陷清单。

## 范围与方法

- 先复算台账分母、状态计数、roadmap 对照关系及兼容/维护便利面的排除情况。
- 对每条已闭环动线分别核验 CLI、公开 SDK、Plan composite preflight、Agent 离线发现四面。
- 沿真实代码路径和契约/测试证据核验 `schema_version` envelope、空/部分失败/能力缺口三态、未登记字段 fail-closed。
- 对 `gravity.agent-call-bound.v1` 的声明逐条与实际调用路径对照，重点复核 9 条 `--resolve-inputs` 后为 `1 / 2` 的动线是否在第一次调用交付完整目录。
- 全仓扫描“设计不适用”及同义豁免，确认例外是否唯一。
- 对不能在 0 次生产 HTTP 的边界内证明的项目明确标为“离线验不了”，列出所缺证据。

## 证据标准

- 每个缺陷必须附当前 worktree 可执行的离线复现命令；否则标为“疑似，未坐实”。
- 文件证据记录相对路径和行号；动态证据记录完整命令、退出码与必要的结构性输出，不记录任何敏感值。
- 不修改实现、测试、文档、契约或 baseline；只写 `tmp/codex/closure-audit/`。

## 完成条件

- 32 条均有判据 1..6 的逐项结论。
- 4 个交回判断题有明确答案。
- 运行指定 `unittest`、`pytest`、`quality check`，记录实际数字；全过程生产 HTTP 请求为 0。
